# 개발 과정과 검증

## 결정의 흐름

1. 아이폰에서 글·사진·영상을 자유로운 순서로 기록하고 AI에 전달하려는 요구로 시작했습니다. 기록은 로컬에 두고, Markdown은 AI가 읽기 쉽게 블록 순서를 보존하도록 설계했습니다.
2. 첫 구현은 Expo Router 기반의 iOS/웹 공통 소스로 만들었습니다. Expo Go로 실제 기기에서 실행했지만 개발 서버와 Expo 계정에 의존했습니다.
3. PC 없이 iPhone에서 열기 위해 웹 빌드와 PWA 지원을 추가했습니다. 첨부가 없는 경우 MD만, 사진·영상이 있는 경우에만 해당 내보내기 옵션을 보여주도록 했습니다. AI용 경량 사본과 원본 전체 백업을 분리했습니다.
4. 초기 `chatgpt.site` 배포에서는 인증 경로와 iPhone Chrome의 브라우저·홈 화면 실행 경로가 충돌해 `ERR_FAILED`가 발생했습니다. 고정된 공개 주소가 필요해 `dodo0314/dodo0314.github.io`의 GitHub Pages로 이전했습니다. 배포 저장소에는 실행 파일과 코드만 두고 개인 기록은 브라우저에 남기는 구조입니다.
5. OneDrive 원본 백업에는 Microsoft Entra SPA 앱 등록과 현재 Pages 주소의 리디렉션 URI가 필요했습니다. 이전 주소만 등록된 상태에서는 `redirect_uri` 오류가 났고, 새 주소를 등록한 뒤 로그인 흐름이 동작했습니다.

## 현재 확인된 상태

사용자가 iPhone Chrome 일반 탭과 새 홈 화면 아이콘에서 GitHub Pages 주소가 정상 실행되는 것을 확인했습니다. OneDrive 백업 흐름도 사용자에게 동작한다고 보고받았습니다. 이 기록은 OneDrive에 ZIP이 실제로 생성됐는지까지 검증한 증거는 아니므로, 앱 폴더의 파일 확인이 필요합니다.

원본 소스는 `app/`에 있고, 공개 사이트가 제공하는 빌드 결과는 저장소 루트에 있습니다. 이번 문서·소스 추가는 앱 런타임을 바꾸지 않습니다. 로컬에서 테스트·lint·typecheck·PWA 빌드를 실행할 수 있으며, 실제 iPhone 사진 권한, 영상 코덱, 브라우저 메모리 한계, OneDrive 파일 확인은 별도 기기 검증 영역입니다.

## 현재 제한

- 백업 ZIP을 앱으로 다시 가져오는 복원 기능과 기기 간 자동 동기화는 없습니다.
- 큰 영상이 많은 ZIP 생성은 iPhone 브라우저 메모리 한도에 영향을 받을 수 있습니다.
- 영상 대표 장면은 소리나 전체 움직임을 보존하지 않습니다.
- 브라우저 데이터 삭제나 다른 주소로의 이동은 로컬 기록을 자동 이전하지 않습니다.
